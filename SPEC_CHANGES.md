# Deliberate changes to the specification

Reference: `CPD2_Code_Workflow.md` v0.1. Principle 1 of the spec: *"If the code and the spec disagree, fix the spec deliberately, not silently."* Each change below is a decision of the authors (19 October 2026), recorded with its rationale and evidence. Every change that affects the method's output is also swept back to its original specification value in the sensitivity grid (`run_sensitivity_grid`, Table 4), so its effect can be reported.

The settings were fixed **before** the full simulation study and the real-data runs. They must not be re-tuned on the real datasets.

## Technical corrections (implementation, not modelling choices)

These bring the code in line with the spec rather than changing it:

- **Robust standardisation.** All models are fitted on (y − median) / (MAD(diff y)/√2) and back-transformed. μ₁ ~ N(0, 100²) on that scale, replacing a location-dependent N(0, 100σ²).
- **Pure horseshoe+ in the Gibbs sampler, as specified.** The regularised slab is an option of the Stan reference only (`use_slab`), as P3 allows.
- **Exact conditional updates.** Truncated-normal φ proposal, σ² shape, slice-sampler Jacobian, CAPA offset in the dynamic log-variance likelihood, and ρ initialised so that `dsp` updates it.
- **Non-centred ρ update.** In the dynamic outlier model, ρ is additionally updated by Metropolis steps that hold the log-volatility innovations fixed and rebuild h̃ by the AR recursion (exact; unit-tested). On the base-cell simulation this raised the bulk ESS of ρ from about 5 to about 46 per 20,000 draws, and all globals reach R-hat ≤ 1.09.
- **Decision functionals traced.** Each retained draw records the number of shift windows and of points exceeding their thresholds. These are invariant to whether a spike is represented in μ or ψ, and are summarised (R-hat, ESS) with the global parameters.
- **Collective segments end at t₂ − 1.** With ω_t = μ_t − μ_{t−1}, the return step at t₂ means the excursion is t₁, …, t₂ − 1.
- **Baselines that assume independent noise** (PELT, robust FPOP / robseg, CAPA without prewhitening) are run on y scaled by its robust *marginal* noise SD, MAD(Δy)/√(2(1 − φ̂)). Scaling by the innovation SD understated their noise level under AR(1) and made them over-segment. Their penalties are the packages' documented defaults (PELT: MBIC; robseg: λ = 2 log n, threshold 3) and are not tuned.

## Corrections of 21 October 2026 (review of the 21 October pipeline run)

The status section previously here ("all gates re-run and passing") was not accurate and has been replaced. Corrections made in this round:

- **FPNN is now the JISPS method.** `R/61_fpnn.R` + `src/ev_decafs_dp.cpp` port the two-phase pipeline of `ev-decafs-serve` (AR(1) estimates → EV-DeCAFS grid DP under the flat BIC penalty 2 log n → five change features → BOCPD-oracle labels refined by Algorithm 3 → SMOTE → Fourier PNN), run without ground truth. Every stage except SMOTE (which uses R's RNG) matches the Python code to machine precision on a stored reference series (`tests/testthat/test-61-fpnn.R`). The previous `baseline_fpnn` was the unsupervised sliding-window heuristic, and the tables of the 21 October run were produced before it was edited.
- **NSP baseline uses `nsp_poly_ar`**, the variant of the proposed method's front-end (C1). `nsp_poly_selfnorm` is miscalibrated under AR(1) noise (gate P2) and would make the "NSP alone" baseline fail for a reason unrelated to NSP.
- **Change-point margin as in Section 6.** ±5 points for n ≤ 1000, scaled by n/1000 above. The code used max(2, round(5n/1000)), i.e. ±2 at n = 500 and on the n = 300 ablation series.
- **Geweke (2004) test rewritten** (`tests/test_geweke_getting_it_right.R`). The successive-conditional kernel is the production chain (`run_gibbs_chain(geweke_fun = , init_state = )`), in the production configuration (dynamic outliers, CAPA offset, κ ≠ 1, τ_ω sampled, marginal-scale MH steps) and in the plug-in / independent-outlier configuration. Each of 4,000 chains starts from an exact joint draw (including the Makalic–Schmidt and Pólya–Gamma auxiliaries) and runs 100 sweeps; under a correct sampler the final states are exact joint draws, so no mixing is assumed (a single long joint chain random-walks over the horseshoe+ prior's levels and scales and did not converge). The forward simulator matches the code's priors exactly (φ prior truncated by rejection, μ₁ ~ N(0, 100²), the sampler's [1e-12, 1e12] variance guard); σ² gets a proper IG(3, 2) prior through the production `update_sigma2`; test functions are bounded or logs of scales. Result: both configurations pass (all Bonferroni p ≥ 0.2), and a planted error (wrong σ² prior in the sampler) is detected (z = −37). The previous script used its own σ² update, a different μ₁ prior, a clipped φ prior and four test functions with no finite mean, and was not part of the P4 gate.
- **Speed: hot loops in C++** (spec P4). The (μ, ψ) banded Cholesky (`src/gibbs_fast.cpp`, replacing `spam`), the tridiagonal log-volatility draw inside a line-for-line copy of `dsp::sampleDSP` (draw-for-draw identical to dsp; unit-tested) and the AR recursion of the ρ update. About 3× faster per iteration at n = 1000.
- **P4 records the real time** at the run length that converged on well-log, instead of rescaling the 50,000-iteration run to 10,000 iterations; the speed target is reported, not gated, as the spec words it.
- **Real data at the converged length.** The proposed method is fitted on the four series with 4 chains × 50,000 iterations (25,000 burn-in), the length that passes the P4 mixing criterion on well-log; mixing is checked per series.
- **Single-change DGP.** `simulate_series(k0 = 1)` now places the change at 0.5 n (it was 0.12 n, i.e. t = 10 for the P5 pilot with n = 80, contrary to the gate's own description). Only P5 and unit tests use k0 = 1.
- **P8 resumability without `targets`.** `targets` is not installed in the project library; `tests/run_p8_full.R` writes one file per (cell, replicate) and skips finished tasks on a rerun.

### Decisions of 21 October 2026 (authors)

- **Defaults unchanged after the ablation diagnosis.** The single-series ablation of the 21 October run (n = 300, φ = 0.5) showed the full model finding none of 5 shifts and only the no-AR(1) ablation finding them. Diagnosis: on short series dense in structure the AR(1) coefficient is overestimated (φ̂ ≈ 0.77 for φ = 0.5) and absorbs the level shifts (the φ–trend confounding of Section 9). The result holds when the chains start at the true μ and with 20,000 iterations, so it is a property of the posterior, not of mixing. Neither a uniform prior on (φ + 1)/2 nor sampling τ_ω changes it. Over replicates, removing AR(1) raises recall but loses precision as φ grows (6 replicates: CP precision 0.54 at φ = 0.6 and 0.21 at φ = 0.9, against 0.96 and 0.81 for the full model), so the single-series ablation was misleading. In general the method is conservative at α = 0.05 (CP precision 0.8–1.0, recall 0.2–0.5). The authors chose to keep the defaults, fixed before the full simulation study, and to report this.
- **Ablation and sensitivity are replicated**: 20 replicates of the P8 base cell and 20 of the n = 300 setting, every configuration on the same series, mean (Monte Carlo SE) reported (`tests/run_p9_replicated.R`).
